# SafeRouter Receipt Desk

Receipt Desk reconciles one SafeRouter API call with a pre-authorized rate card. The browser recomputes the charge and checks a buyer authorization and an issuer receipt signature. It uses P-256 application keys. The issuer attests the gateway response and customer activity record. TapeOut hosts the verifier and its release policy. The verifier does not make payments or obtain independent evidence of the underlying model execution.

## Offline demo

Requires Node 20 or later. Run `node self-check.mjs` for the original signature fixture and `node studio-check.mjs` for the full controlled-call reconciliation using a mocked SafeRouter wire response. Run `node build.mjs fixtures/studio-manifest.json` to rebuild the synthetic demo. Serve the directory on localhost and open `index.html`. Choose `fixtures/studio-bundle.json` and `fixtures/studio-buyer.json`. Use `fixtures/studio-tampered.json` to check the rejection. The simulated charge is 69 nano-USD on 24 input and 7 output tokens.

## Studio execution

A live call requires a dedicated, unbilled SafeRouter studio key, its authenticated route and effective account prices, a confirmed X Layer release container, and explicit authorization for the request charge. Use one operator and one private journal for this key and quote. Keep credentials and private artifacts outside the source directory. A different operator or journal must never use the same key.

1. Generate two application keypairs with `node studio.mjs keygen PRIVATE_JWK PUBLIC_JWK`. Use separate files for the buyer and the issuer. Private files must have owner-only permissions. Keep the buyer public key in the buyer's authorization record and the issuer public key in the release manifest.
2. Make a manifest matching the fields of `fixtures/studio-manifest.json`. Set the authorized chain 196 container and version (for example `v1`). Enter the confirmed gateway model, the explicit SafeRouter routing pin and its public activity label, effective account input and output rates in nano-USD per million tokens, and bounds for a single short text request. The demo values are synthetic. Confirm the provider response reports zero cache usage explicitly and uses the configured model label. Use a public direct route if the internal routing pin is confidential.
3. Pre-sign with `node studio.mjs quote MANIFEST BUYER_PRIVATE CAP_NANO_USD AUTH_OUTPUT`. The authorization expires after five minutes. It binds the release policy and issuer key, per-token rates, fixed studio request profile, nonce and spending limit. The largest quoted charge within the stated input and output bounds must fit the cap. The CLI caps the quote at 1,000,000 nano-USD ($0.001).
4. Check the key with `node studio.mjs preflight MANIFEST AUTH BUYER_PUBLIC API_KEY_FILE`, which makes only authenticated GET requests. When authorized to incur the live call charge, run `node studio.mjs run MANIFEST AUTH BUYER_PUBLIC ISSUER_PRIVATE API_KEY_FILE JOURNAL BUNDLE_OUTPUT --execute-live`. The API key file must be owner-only. The dedicated key must start with empty activity, zero lifetime spend, zero input/output tokens and zero allowance spend and a positive one-time allowance no higher than the quote cap. The gateway's allowance is a pre-dispatch exhaustion check, so it can be exceeded on a call that settles above the estimate. The quote cap applies to receipt issuance. Confirm effective prices and upstream limits before dispatch.
5. Keep the journal if the call fails or times out. Dispatch consumes the quote and key in that journal, including ambiguous failures. A pending output indicates that the tool did not write a signed receipt. Inspect the key's activity before deciding on any follow-up. A billing mismatch produces a private numeric diagnostic in the journal and withholds the receipt. The receipt carries only the application attestation, the token counts, the two amounts and a nonce-salted request commitment. Prompt, response, call ID, account identifiers and keys stay out of it.

The quote uses integer arithmetic and rounds once up to one nano-USD. The issuer separately reads the actual customer debit from the activity endpoint. It accepts equality at nano-USD precision, allowing floating-point error at an integer boundary. Billing correlation uses the isolated key's empty-to-one activity transition, its expected route and token counts, and the gateway call ID and response hash. The activity endpoint does not return a matching call ID. The production activity response does not expose per-request upstream cost. Obtain that separately from an authorized provider invoice or metering record if required.

## Release preparation

Use `node prepare-publish.mjs CONTAINER AUTHORIZED_WALLET MANIFEST NEW_HTML_PATH` with the wallet and open container independently resolved from the intended TapeOut processor and circuit. The tool checks the X Layer chain and the SiteRegistry implementation via two RPC providers, requires an unused `vN/index.html` path, creates the local verifier and requests two gas estimates. Its standard output is unsigned transaction data. Synthetic manifests are rejected.

The registry's `putFile` replaces existing content. Recheck the exact path and deployment authorization immediately before any authorized signing and broadcast, and serialize writes by that wallet. Check gas cost before signing. After confirmation, use an independent TapeOut reader to compare the on-chain bytes with the release file and SHA-256, then open that versioned path and test a signed sample and a tampered copy. Preserve historical paths and their local release manifests.

## Container acquisition plan

Run `python3 plan-container.py --processor 409` to read both RPC providers at the same confirmed block and prepare one NAND mint, its two-input/one-output tapeout, and an opening template. The default processor zero is checked for capacity before templates are emitted. The processor 409 snapshot in `container-plan-409.json` has 99,860 remaining transistors and requires 0.08196 OKB before network gas. Refresh this snapshot before an authorized transaction.

After a real tapeout confirms, run `python3 plan-container.py --processor 409 --wallet PUBLIC_ADDRESS --mint-tx MINT_HASH --tapeout-tx TAPEOUT_HASH`. The tool checks the canonical successful transaction and matching ERC-721 Transfer/TapedOut events, validates current ownership, derives the actual container and emits the opening calldata. Each transaction depends on the preceding confirmation. The tool uses only RPC reads and never obtains signing keys. The function and event definitions were checked in the [official TapeOut client bundle](https://tapeout.net/app/assets/index-DsAkZLRU.js).

The user signing page is `wallet-steps.html`. Serve this directory on localhost and open the page in the wallet-enabled browser profile. It discovers EIP-6963 providers, requires the designated studio address on chain 196, imports a verified plan and requests one transaction only when the user clicks the signing button. It checks the current nonce, balance, gas, protocol fee and 0.09 OKB budget. Each nonce is recorded in local storage before a wallet request, so unresolved requests require operator reconciliation.

Prepare mint with `python3 plan-container.py --processor 409 --wallet 0x91000b484b5d4d5ba888c8a2f5dbdbbbcbf788d2`. After its confirmed successful receipt, add `--mint-tx HASH` to prepare tapeout. After the tapeout receipt, add `--tapeout-tx HASH` as well to prepare opening. Each plan includes cumulative actual receipt costs, the current gas limit/price ceiling, and reserved future transaction values. Future gas is estimated when each later step becomes executable. Refresh and import a new plan after each confirmation.

The planner keeps `https://rpc.xlayer.tech` as its primary endpoint. Choose the independent comparison endpoint with `--second-rpc https://xlayer.drpc.org` or `TAPEOUT_SECOND_RPC=https://xlayer.drpc.org`. The allowed comparison endpoints are the existing OKX endpoint and dRPC. Every field except the observed optional transaction `blockTimestamp` extension remains subject to comparison. The observed extension difference is recorded in `rpc-tx-provider-difference.json`.

## Explicit one-call authorization and private evidence

The SafeRouter UI allocates at least $0.01 to a key. To use this allocation for the authorized single short call, add `--operator-cap-nano-usd 1000000` to both `preflight` and `run`. This mode permits remaining key allocation up to $0.01, requires a signed quote cap within the operator cap, fixes maximum output to 8 tokens, and allows at most 128 input tokens. The fixed request remains `Reply with the single word OK.`. The effective CM rate policy in `release-policy-v1.json` quotes at most 12,096 nano-USD ($0.000012096) within these token bounds. The operator cap governs dispatch authorization and receipt acceptance. The gateway's allocation check can be crossed at settlement.

Preflight uses only GET requests and reports the separate allocation, signed quote cap, operator cap and worst-case quoted amount. Authenticated GETs increment SafeRouter's request counter. An unbilled key is identified through empty activity, zero lifetime cost, zero input/output tokens and zero allowance spend.

For a live run, place JOURNAL outside the project source in the private Sumplus configuration directory. The run saves the original release manifest, pre-signed buyer authorization and public buyer key in `context-<id>.json`. Each wire response is saved as raw `.bin` plus a `.json` record before JSON or shape validation. Required evidence headers are retained. Authorization and cookie headers are excluded. Capture files use mode 0600, and the directory requires private permissions. Post-call activity and key observations are attempted after a malformed or timed-out response. A POST is attempted once.

Use `node studio.mjs replay PRIVATE_CONTEXT ISSUER_PRIVATE NEW_BUNDLE_OUTPUT` after an adapter correction. Replay verifies the original pre-signed quote and captured request sequence, checks raw-byte hashes and uses original captured completion times. It makes no network requests. Raw captures contain private request, response and account material and must stay outside the public release.

## Publication with the remaining wallet budget

After opening, add `--open-tx OPEN_HASH` to the complete mint/tapeout planner command to recheck all three receipts, the actual container owner, token binding and SiteRegistry implementation. Supply `--release-manifest MANIFEST --release-html HTML --verified-bundle BUNDLE --buyer-public BUYER` to prepare the next publish wallet step. The tool verifies the signed receipt against the formal manifest, rebuilds HTML to compare its exact bytes, locks SHA-256 and the versioned path, refuses an occupied path, estimates gas through both RPC endpoints, and checks actual prior spend plus the new gas ceiling against the same 0.09 OKB budget.

The wallet page supports this restricted publish step. Before a user signing request, it checks the actual calldata HTML hash and destination, rechecks the registry implementation and container owner, and refuses an occupied version path. Offline checks are `python3 -B planner-check.py`, `node wallet-check.mjs` and `node studio-check.mjs`.

## Returned model and generation outcome

The buyer quote and release manifest remain on the requested billing model. Receipt domain `sumplus-receipt-v3` also signs `returnedModel`, `finishReason` and `reasoningTokens`. Verifiers continue to accept the previous receipt domains. Requested and billed model identity must match exactly. The verifier permits one explicit returned-model alias on the CM/C line, `deepseek-v4-flash → deepseek-v4.1-flash`. The SafeRouter catalog identifies the requested ID as a legacy V4.1 alias, and the captured CM response reports this exact returned name. The allowed pair is fixed in the verifier source and therefore covered by the release HTML hash. Other returned names require a supported rule.

The studio response reached `finish_reason=length` with 37 input tokens and 8 output tokens, all reported as reasoning tokens. The customer charge is $0.000004452 at the pre-signed effective rates. The UI reports the returned model and generation outcome separately from billing verification. Generation ended at the output limit. The signed receipt establishes agreement between the quoted rate calculation and recorded debit, with usage and outcome attested by the issuer.

Use `node studio-check.mjs` to exercise the exact CM alias, unchanged buyer authorization, signature coverage for outcome fields, unknown alias rejection, usage tampering, private replay, and the generated-page browser stub. Real receipt signing uses `node studio.mjs replay PRIVATE_CONTEXT ISSUER_PRIVATE NEW_BUNDLE_OUTPUT`, which reads the original authorization and preserved wire response locally.
